# 지하철 길 안내 기능 설계

작성일: 2026-11-20

## 목표와 범위

시각장애인과 외국인 관광객이 출발지에서 목적지까지 끊김 없이 안내받는 것이 목표다. 버스·지하철 경로는 TMAP 또는 카카오맵 대중교통 API로, 역 안은 AprilTag 위치 인식으로 안내한다.

| 대상 | 겪는 문제 | 필요한 안내 |
| --- | --- | --- |
| 시각장애인 | 화면과 표지판을 볼 수 없어 통로에서 방향을 잃는다. | 음성·입체 음향 안내, 화면을 보지 않아도 되는 조작 |
| 외국인 관광객 | 한글 표지판과 역 구조를 읽기 어렵다. | 다국어 안내, AR 화살표 |

데모 범위(11/21 발표):

1. 설정된 길찾기 공급자의 대중교통 API로 출발지에서 목적지까지 버스·지하철 경로를 안내한다.
2. 역 안에서는 AprilTag로 위치를 잡고, 태그 사이 구간은 가속도 센서로 보정한다.
3. 역 안 경로를 따라 목적지(승강장 등)까지 안내한다.

## 현재 구현 상태

첫 화면에서 출발지·도착지를 정하면 서버가 조회한 경로를 2D 지도와 단계별 안내로 표시한다. 역에서 AprilTag를 비추면 등록된 공간을 찾아 그 통로의 AR 안내로 전환한다. **태그로 실내 안내**를 누르면 GPS나 실외 경로 없이도 같은 안내를 시작할 수 있다. 메인 화면의 마이크 버튼에서 출발지와 도착지를 대화로 정하고 경로 제안을 수락할 수도 있다. 여러 후보 경로 비교와 목적지별 실내 경로 탐색은 설계 단계다.

| 구성 | 현재 동작 | 위치 |
| --- | --- | --- |
| 위치 추정 | 전체 공간에서 고유한 AprilTag ID로 공간을 찾는다. 기기의 Web Worker가 그 공간에 저장한 태그 크기와 꼭짓점 좌표로 카메라 자세를 계산한다. | `frontend/public/ar/tracker.js` |
| 배치·경로 | 관리자 페이지에서 공간별 모델, 태그 위치·방향과 안내 경로를 편집한다. 기본 예시는 태그 4개와 직진 2 m 후 우회전 1.75 m인 경로다. | `frontend/src/admin/`, `backend/src/station.store.ts` |
| 안내 표시 | 다음 진행 방향을 바닥 위 화살표 하나로 그린다. 태그를 놓치거나 화살표를 놓을 바닥이 화면 밖이면 영상만 보인다. | `frontend/src/ar/camera.ts` |
| 역 안내판 | 사진 한 장 또는 카메라 세 프레임을 서버로 보낸다. 한국어 OCR로 읽은 역명·번호를 노선의 인접역과 대조하고, 안내판에서 읽은 화살표가 가리키는 방면을 표시한다. | `frontend/src/SignReader.tsx`, `backend/signs/` |
| 기록·3D | 사진, 자세, 가속도, 영상을 서버에 저장하고 점군을 복원한다. LiDAR 스캔 첨부도 받는다. | `frontend/src/ar/recording.ts`, `backend/` |
| 배포 | Caddy HTTPS로 `home.soohyuk.dev`에서 서비스한다. | `compose.yaml`, `deploy/` |
| 실외 길 안내 | 서버는 키 설정에 따라 TMAP 또는 카카오맵을 사용해 장소와 도보·대중교통 경로를 조회한다. 2D 지도와 세로 목록에 전체 경로를 표시하고 GPS 진행에 따라 현재 구간을 강조한다. AR에서 같은 경로로 돌아올 수 있다. | `backend/src/directions/`, `frontend/src/navigation/` |

첫 화면에서 **AR 카메라 → 안내판 읽기**를 열어 판독을 시작한다. 안내판의 방면은 바닥에 표시되는 안내 경로와 독립적으로 결정한다. 서버는 CPU로 OCR을 실행하고 여러 요청에서 모델을 재사용한다. [지원 표지와 사용법](../README.md#역-안내판의-현재역과-방면-읽기) · [실사진과 응답 시간 시험](../experiments/station-signs/2026-11-20-performance.md)

## 사용자 흐름

사용자는 채팅이나 음성으로 목적지를 말하고, 안내는 음성·입체 음향·AR 화살표로 받는다. 역 입구의 첫 태그를 인식하면 실외 안내에서 역 안 안내로 바뀐다.

1. **목적지 입력**: 채팅 또는 음성 인식으로 "서울역에서 4호선 타고 싶어" 같은 문장을 받는다.
2. **LLM 해석**: 문장을 목적지 좌표와 역 안 목적지(승강장·출구)로 바꾼다. 모호하면 되묻는다.
3. **실외 안내**: 설정된 대중교통 경로 API로 현재 위치에서 목적지까지 버스·지하철 경로를 받아 지도와 음성으로 안내한다.
4. **역 안 전환**: 입구 근처에서 카메라를 켜도록 안내하고, 입구 태그를 인식하면 역 안 모드로 바꾼다.
5. **역 안 안내**: 태그로 위치를 잡고 태그 사이는 가속도 센서로 추정한다. 갈림길·회전 지점마다 음성과 입체 음향으로 방향을 알리고 화면에는 바닥 화살표를 그린다.
6. **도착**: 목적지 노드에 닿으면 도착을 알리고 안내를 끝낸다.

언어는 한국어와 영어를 지원한다.

## 위치 추정과 경로 데이터

실외 구간은 서버의 길찾기 공급자 인터페이스를 통해 버스·지하철 경로를 받는다. 역 안 위치는 AprilTag로 절대 위치를 잡고, 태그 사이는 가속도를 두 번 적분해 이어 붙인다. 역 안 지도는 LiDAR 스캔 데이터로 만든다.

| 구간 | 방식 | 정해진 내용 | 남은 위험 |
| --- | --- | --- | --- |
| 실외 경로 | TMAP 또는 카카오맵 대중교통 경로 조회 | 버스·지하철·도보 구간을 공통 형식으로 제공한다. 두 키가 설정되면 TMAP을 사용한다. | 데모 출발지와 도착지에서 실제 반환되는 환승 경로와 안내 문구를 확인해야 한다. |
| 실내 전환 | 입구 AprilTag 인식 | 첫 태그를 인식하면 역 안 모드로 바뀐다. | 없음 |
| 절대 위치 | AprilTag 자세 추정 | 지금 코드(`tracker.js`)를 그대로 쓴다. | 없음 |
| 태그 사이 | 가속도 이중 적분 | 마지막 태그 자세에서 시작해 다음 태그를 보면 오차를 초기화한다. | 휴대폰 가속도 센서는 수 초 안에 수 m씩 오차가 쌓일 수 있어 태그 간격을 좁게 둬야 한다. |
| 역 안 지도 | LiDAR 스캔 | 스캔 데이터를 역 안 지도의 원천으로 쓴다. | 관리자 페이지에서 OBJ 표면에 태그를 배치한다. 스캔을 안내용 모델로 단순화하는 과정이 필요하다. 태그를 촘촘히 붙여 드리프트를 줄인다. |

[프로젝트 공급자 설정](../README.md#장소-검색과-도보대중교통-길찾기-api) · [TMAP 대중교통 명세](https://transit.tmapmobility.com/docs/routes) · [카카오맵 REST API 문서](https://developers.kakao.com/docs/ko/kakaomap/rest-api)

## AI 기능

필수 AI 기능은 채팅과 음성으로 말한 목적지를 LLM으로 해석하는 것이다. 실외 경로 대화는 NestJS가 CLIProxyAPI를 통해 모델을 호출하고 장소 검색과 경로 조회 도구를 실행한다. 브라우저 음성 인식이 가능한 기기에서는 말한 내용을 확인한 뒤 전송한다. 아래 표는 실내 안내를 포함한 전체 설계다.

| 기능 | 우선순위 | 모델 | 역할 |
| --- | --- | --- | --- |
| 음성 인식 | 필수 | Whisper | 음성 명령을 텍스트로 바꾼다. |
| 목적지 해석·대화 | 필수 | GPT | 문장을 목적 역, 역 안 목적지 노드, 조건으로 바꾸고, 모호하면 되묻는다. 한국어·영어로 답한다. |
| 음성 안내 | 필수 | OpenAI TTS | 회전·도착 안내를 읽어준다. 방향은 입체 음향으로도 알린다. |
| 장애물 인식 | 선택 | 미정 | 카메라 영상에서 앞의 장애물을 경고한다. |
| 표지판 인식·번역 | 선택 | 미정 | 비친 표지판을 읽고 번역한다. |
| 주변 상황 설명 | 선택 | 미정 | 현재 화면을 말로 설명한다. |

실외 경로 대화는 `POST /api/assistant`를 사용한다. 서버는 장소 검색으로 받은 지점과 사용자가 선택한 지점으로 경로를 조회한다. 향후 실내 목적지 선택은 역 안 지도에 등록된 노드로 제한할 예정이다.

## 결정 사항과 열린 질문

시연은 환승역 환승 통로 하나만 실제로 보여주고, 복도 지도를 실제 환승역에 대입한다. LiDAR 스캔은 LLM이 작성한 코드로 단순한 모형으로 바꾸고, 태그는 웹 편집기에서 배치한다.

| 항목 | 결정 |
| --- | --- |
| 대상 | 시각장애인, 외국인 관광객 |
| 실외 경로 | TMAP 또는 카카오맵 대중교통 경로 API(버스·지하철) |
| 역 안 안내 구간 | 출발역 입구→승강장, 환승역 환승 통로, 도착역 승강장→출구 |
| 실연 범위 | 환승역 환승 통로만 복도에서 실연 |
| 역 연결 | `abc` 복도를 초지역 4호선 → 서해선 환승 통로로 사용한다. 0번 태그(4호선)에서 출발해 1번 태그에서 좌회전하고 2번 태그(서해선)에 도착한다. 데모 경로는 정왕역 → 초지역(환승) → 소사역이다. |
| 실내 전환 | 입구 AprilTag 인식 |
| 역 안 위치 | AprilTag + 가속도 이중 적분, 태그를 촘촘히 부착 |
| 역 안 지도 | 복도를 LiDAR로 측정해 OBJ로 내보내고, LLM이 작성한 단순화 코드로 세부를 줄여 구조만 남긴 모형을 다시 만든다. 모형에는 경로 그래프를 담는다. 엘리베이터 관련 기능은 넣지 않는다. |
| 태그 배치 | 웹 편집기에서 모형 위에 배치 |
| 입력 UI | 채팅 + 음성 인식 + LLM |
| 출력 | 음성 안내, 입체 음향(Web Audio PannerNode, 이어폰), AR 화살표. 화면은 카메라 위에 채팅 시트를 올린다. |
| AI 스택 | OpenAI(Whisper, GPT, TTS), NestJS 백엔드가 호출 |
| 언어 | 한국어, 영어 |
| 시연 장소 | 교내 복도를 가상 환승역으로 |
| 프록시 남용 방지 | 하지 않는다. |

- [ ] 데모에 사용할 공급자의 키를 입력해 정왕역 → 소사역에서 초지역 4호선 → 서해선 환승 경로가 반환되는지 확인한다.
